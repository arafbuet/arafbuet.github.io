Selected Work

Three end-to-end case studies with real outputs, metrics, and code links.

Khulna Division LULC Change Mapping (1994–2024)

Problem
Quantify 30-year land-cover dynamics across Khulna Division (5 classes: Water, Aquaculture, Settlement, Vegetation, Agriculture) with ecosystem service valuation and statistical hotspot detection.
Approach
Built in Google Earth Engine, then ported to a reusable Python pipeline (Microsoft Planetary Computer STAC). Annual median composites from Landsat Collection 2 L2 + Sentinel-1 RTC, gap-filled with JRC Global Surface Water and Copernicus DEM. Supervised Random Forest classification per epoch. Added ESV estimates per class, transition matrices (km²/ha), and Getis-Ord Gi* hotspot analysis on a 1 km grid. Pilot validation on a 6×6 km area.
Result
Four epoch maps (1994, 2004, 2014, 2024) with transition matrices and Gi* z-score/significance maps. Pilot test overall accuracy 0.91 and 0.95. Reproducible GEE scripts and Python (xarray/rioxarray) modules. Map layouts in ArcGIS Pro.
Stack
Google Earth Engine (JS API), Python (STAC, xarray, rioxarray, scikit-learn), Landsat C2L2, Sentinel-1 RTC, JRC-GSW, Copernicus DEM, ArcGIS Pro 3.1

Bangladesh Crop Pattern AI (IWFM, BUET)

Problem
Map seasonal crop types nationwide to support hydrological modeling and water-demand estimation for integrated water resources management.
Approach
Satellite time-series analysis using Sentinel-1 (SAR) and Sentinel-2 (optical) data. NDVI/EVI phenology extraction per season. Machine learning classification (Random Forest, CNN architectures) trained on ground-reference data. Integration with hydrological models for water-demand estimation.
Result
Crop type maps per season, trained classification models, integrated water-demand estimates. Collaborative research outputs under IWFM Water Resources Development program.
Stack
Google Earth Engine, Python, Sentinel-1/2 time series, Random Forest, CNN, xarray, scikit-learn, PyTorch

Multi-Model AI Evaluation & Orchestration Framework

Problem
Free-tier LLMs vary wildly in reliability. Need a system that routes tasks to the right model, verifies outputs, and produces a calibrated scoreboard for code review and research tasks.
Approach
Built a delegation framework with four roles: Builder (writes code), Fixer (patches bugs), Checker (verifies correctness), Researcher (gathers context). Verification loops with automated test execution. Calibration exam: 51 models across 8 providers evaluated on planted bugs and trap tasks. Whole-codebase review pipeline using free models with finding deduplication.
Result
Calibration exam completed across 51 models. Whole-codebase review pipeline confirmed 39 unique findings. Framework routes tasks dynamically, retries on failure, and outputs a scoreboard with pass/fail rates per model per role.
Stack
Python, MCP (Model Context Protocol), OpenAI-compatible APIs, asyncio, pytest, GitHub Actions

How I Work

Four steps from problem definition to reproducible delivery.

1. Scope & Data Audit

Define AOI, epochs, classes, and validation protocol. Inventory available imagery (Landsat, Sentinel, radar, DEM) and reference data. Agree on metrics (OA, Kappa, per-class F1) and deliverable formats.

2. Pipeline Construction

Build in GEE for rapid iteration, then port to Python (STAC/xarray) for reproducibility. Composite → gap-fill → classify → post-process. Version control from day one. Unit tests on critical transforms.

3. Validation & Analysis

Independent accuracy assessment (stratified random sampling). Transition matrices, ESV computation, Gi* hotspot analysis. Statistical significance testing. All intermediate products saved for auditability.

4. Delivery & Handoff

COG/GeoPackage rasters, CSV stats, PDF maps, reproducible notebooks, requirements.txt, and a methods note. Walkthrough call included. Code stays on GitHub (private or public per agreement).
